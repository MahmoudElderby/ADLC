# Spec Tracking

## Purpose

ADLC uses Spec Kit for feature-level specification work. Each feature spec lives
under `specs/NNN-feature-name/`, but the project also needs a single place to see
all specs, their status, and the next required action.

Use `specs/README.md` as the live project spec registry.

## Spec Lifecycle

Each feature moves through this lifecycle:

```text
Proposed -> Spec Draft -> Clarifying -> Ready for Plan -> Planned -> Tasked -> Implementing -> Done
```

Status meanings:

- `Proposed`: idea is known, but no Spec Kit feature folder exists yet.
- `Spec Draft`: `$speckit-specify` created the feature spec.
- `Clarifying`: open questions are being answered through `$speckit-clarify`.
- `Ready for Plan`: spec is approved and clear enough for `$speckit-plan`.
- `Planned`: implementation plan exists.
- `Tasked`: implementation tasks exist.
- `Implementing`: code work has started.
- `Done`: accepted and complete.

## Registry Rules

Every feature spec MUST have one row in `specs/README.md`.

The registry row records:

- spec number
- name
- status
- owner or decision lead
- feature directory
- current artifact
- next action
- notes

Update the registry whenever:

- a feature is proposed
- `$speckit-specify` creates a feature folder
- clarification starts or finishes
- a plan is created
- tasks are created
- implementation starts
- the feature is accepted as done

## Feature Folder Convention

Spec Kit creates feature folders under `specs/` using sequential numbering:

```text
specs/001-r0-agent-fleet-control-plane/
specs/002-agent-registry/
specs/003-platform-chat/
```

Each folder may contain:

- `spec.md`
- `plan.md`
- `tasks.md`
- `checklists/`
- supporting research or notes generated by Spec Kit

The registry is the table of contents. The feature folder is the source of truth
for the feature itself.

## First Planned Spec

The first recommended feature spec is:

```text
R0 agent fleet control plane walking skeleton
```

Its purpose is to define the smallest end-to-end product slice:

- register skills and MCPs
- create and publish an agent
- start an OpenAI-managed session in the self-hosted workspace
- track a Markdown artifact reference
- show operational state in Command Center
- inspect session/workflow trace and audit history
- use Platform Chat for grounded status questions
