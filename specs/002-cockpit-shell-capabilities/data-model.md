# Data Model: Cockpit Shell and the Capability Registry, For Real

This model **extends** `specs/001-r0-agent-fleet-skeleton/data-model.md`. Unchanged 001 tables (agents, sessions, events, artifacts, live fleet) remain owned by later slices. This document specifies only what slice 002 must create, alter, or start using for real.

## Conventions (unchanged)

- Primary keys are UUIDs generated by ADLC.
- All timestamps are UTC with timezone.
- Every workspace-owned row includes `workspace_id`.
- Secret values are encrypted through the Observability and Governance encryption boundary and are never present in ordinary configuration JSON or HTTP DTOs.
- Audit records are append-only.
- Cross-module writes use application-service ports; shared database access does not grant write ownership.

## Enumerations

### Capability validation status

`pending_validation | valid | invalid`

Existing PostgreSQL enum `validation_status` currently also contains `unreachable`. Slice 002 keeps `unreachable` on that enum for MCP reachability compatibility with shipping SQL, and adds `unverified` via migration. Application code must treat MCP health as two fields (below) rather than one overloaded status.

### MCP reachability status

`unverified | reachable | unreachable`

Stored on `mcp_servers.reachability_status` (new). Mapping from the legacy single `status` column during rollout:

- environment offline or check unanswered → `unverified` (amber)
- handshake succeeded and allowed tools present → `reachable` plus validation `valid` (emerald)
- handshake failed or none of the allowed tools advertised → `unreachable` (red)
- schema/label/URL errors before a check is issued → validation `invalid`; reachability stays `unverified`

### Connector status (unchanged)

`offline | online | degraded`

A connector is `offline` when `last_heartbeat_at` is null or older than 30 seconds.

### Environment check type

`mcp_reachability | environment_health`

### Environment check status

`pending | claimed | answered | expired | rejected`

### Session (auth) status

`active | revoked | expired`

## New Tables

### `workspace_users`

Owned by Observability and Governance (identity is a control-plane concern; there is no separate Identity module in R0).

| Field | Type | Rules |
|------|------|-------|
| `id` | uuid | Primary key |
| `workspace_id` | uuid | Required FK; R0 has one user per workspace |
| `email` | text | Required, unique, case-insensitive |
| `display_name` | text | Required; shown in the top bar and audit attribution |
| `password_hash` | text | Argon2id; never selected into product DTOs |
| `created_at` | timestamptz | Required |
| `updated_at` | timestamptz | Required |

Constraint: unique `(workspace_id)` for R0 (single operator). Unique `email`.

Bootstrap inserts this row from deployment env. No self-service insert path.

### `authenticated_sessions`

Owned by Observability and Governance.

| Field | Type | Rules |
|------|------|-------|
| `id` | uuid | Primary key |
| `workspace_id` | uuid | Required FK |
| `user_id` | uuid | Required FK to `workspace_users` |
| `token_hash` | text | SHA-256 of the cookie token; unique |
| `status` | text | `active`, `revoked`, or `expired` |
| `created_at` | timestamptz | Required; absolute expiry is `created_at + 24h` |
| `last_seen_at` | timestamptz | Required; idle expiry is `last_seen_at + 8h` |
| `expires_at` | timestamptz | Required; min(absolute, next idle bound), updated on activity |
| `revoked_at` | timestamptz | Nullable |

The raw cookie token is shown only at issuance (Set-Cookie) and is never stored or logged.

### `environment_checks`

Owned by Workspace Environment Settings.

| Field | Type | Rules |
|------|------|-------|
| `id` | uuid | Primary key |
| `workspace_id` | uuid | Required FK |
| `connector_id` | uuid | Required FK |
| `check_type` | text | `mcp_reachability` or `environment_health` |
| `target_capability_id` | uuid | Required for `mcp_reachability`; the MCP id |
| `status` | text | Check status enum |
| `payload_redacted_json` | jsonb | MCP id, URL, allowed tools; **no credential** |
| `result_redacted_json` | jsonb | Reachability, handshake outcome, redacted error; nullable until answered |
| `correlation_id` | uuid | Required |
| `requested_at` | timestamptz | Required |
| `claimed_at` | timestamptz | Nullable |
| `answered_at` | timestamptz | Nullable |
| `expires_at` | timestamptz | Required; default 10 seconds from request |
| `created_at` | timestamptz | Required |

Constraints:

- Connector result rows must reference a check the platform created. Orphan or unexpected `check_id` values are stored as `rejected` if presented, and do not change capability status.
- Expired `pending`/`claimed` checks flip to `expired` and set MCP reachability to `unverified`.
- Credential material used for the handshake is decrypted into the connector poll response body only, never written to this table.

## Extended Tables

### `skills` (existing)

Add:

| Field | Type | Rules |
|------|------|-------|
| `created_by` | uuid | Required FK to `workspace_users` |
| `updated_by` | uuid | Required FK to `workspace_users` |

Existing unique `(workspace_id, name, version)` remains. `updated_at` is the optimistic-concurrency token.

Validation rules:

- `name`, `description`, `source_type`, `source_reference`, `version` required.
- `compatible_environment_types_json` must include `self_hosted` or validation is `invalid` with a blocking error.
- Live draft validation may run without a row; persistence refuses blocking errors.

### `mcp_servers` (existing)

Add:

| Field | Type | Rules |
|------|------|-------|
| `reachability_status` | text | `unverified \| reachable \| unreachable`; default `unverified` |
| `reachability_summary` | text | Redacted, nullable |
| `reachability_checked_at` | timestamptz | Nullable |
| `created_by` | uuid | Required FK to `workspace_users` |
| `updated_by` | uuid | Required FK to `workspace_users` |

Existing unique `(workspace_id, label)` remains and powers FR-020.

Validation rules:

- `label`, `server_url` (http/https), non-empty `allowed_tools`, `connection_origin = environment`, `transport_type = http`, `required` flag, credential reference after first save.
- Register/update accepts write-only `credential` (plaintext in the request only). The API creates/updates `workspace_secrets` of type `mcp_credential` and stores `credential_secret_id`. Subsequent GET/PATCH responses omit the secret.
- PATCH without `credential` keeps the existing secret. PATCH cannot read the old value back to the client.
- Concurrent PATCH: `updatedAt` must match; otherwise 409.

### `workspace_secrets` (existing)

No column change. `encrypted_value` remains `text` (opaque AES-GCM envelope as base64, matching `0001_foundation.sql`, not the 001 data-model `bytea` sketch). Application queries for API DTOs select `id`, `type`, `fingerprint`, `key_version`, `created_at` only.

### `workspace_connectors` and `workspace_environment_settings` (existing)

Used for real. Registration stores `auth_token_hash`. Check-in updates `status`, `version`, `host_fingerprint`, `capabilities_json`, `last_heartbeat_at`. `revoked_at` set on token rotation. One active connector per workspace remains.

`workspace_environment_settings.health_json` stores redacted connector/filesystem/probe-ability, never secrets. Executor availability may be reported as unknown in this slice; 002 does not start executors.

### `audit_log` (existing)

Used for real. Trigger `prevent_audit_log_mutation` already refuses UPDATE/DELETE.

Required actions in this slice:

- `auth.sign_in`, `auth.sign_out` (sign-in failure may omit actor if unknown; do not disclose whether the email exists in the HTTP response)
- `skill.registered`, `skill.updated`, `skill.removed`, `skill.remove_blocked`
- `mcp.registered`, `mcp.updated`, `mcp.removed`, `mcp.remove_blocked`, `mcp.revalidated`
- `secret.stored` (metadata: type + fingerprint only)
- `environment_check.requested`, `environment_check.answered`, `environment_check.expired`

`metadata_redacted_json` never contains credential values, password hashes, session tokens, or connector bearers. `actor_id` for authenticated actions is the `workspace_users.id` from the session.

### `agent_capability_attachments` (existing, read-only in 002)

Capability deletion queries this table through a Capability Registry port. 002 does not provide agent write APIs. Demo/test setup may insert a published `agents` / `agent_versions` / attachment row as a fixture.

## State Transitions

### Authenticated session

```text
(none) --sign-in succeeds--> active
active --activity--> active (last_seen_at, expires_at updated)
active --idle or absolute timeout--> expired
active --sign-out--> revoked
expired/revoked --any workspace request--> 401 (no workspace disclosure)
```

### Skill

```text
(form) --blocking errors--> not persisted
(form) --save--> pending_validation --> valid | invalid
valid|invalid --edit--> pending_validation --> valid | invalid
any persisted --delete with no attachments--> removed
any persisted --delete with attachments--> unchanged + audit skill.remove_blocked
```

### MCP server

```text
(form) --blocking schema/label errors--> not persisted
(form) --save, connector online--> pending_validation + unverified
                 --check answered reachable--> valid + reachable
                 --check answered failed--> invalid or valid + unreachable (record kept)
(form) --save, connector offline--> valid-or-invalid schema + unverified (reason shown)
unverified|reachable|unreachable --revalidate--> unverified then the check outcome
```

Revalidation of a stored record never discards it.

### Environment check

```text
pending --connector claims--> claimed --result--> answered
pending|claimed --expires_at--> expired (MCP unverified)
pending --unexpected result for unknown id--> rejected
```

## Indexes (002 additions)

- `authenticated_sessions (token_hash)` unique.
- `authenticated_sessions (user_id, status, expires_at)`.
- `environment_checks (connector_id, status, requested_at)` for poll.
- `environment_checks (target_capability_id, requested_at desc)`.
- Existing capability and audit indexes remain.

## Snapshot / DTO Redaction Rules

HTTP resources for skills and MCP servers may include:

- identity: id, label/name, status fields, connection origin, allowed tools, URLs, fingerprints, actor display names, timestamps
- `credentialSecretId` and `credentialHealth`

They must never include:

- `credential`, `encrypted_value`, `password_hash`, `token_hash`, connector bearer, session token
- unredacted upstream error bodies
